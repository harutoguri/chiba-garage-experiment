チバガレージ サイト 指摘まとめ（ホームページ担当者向け）

対象: https://chibagarage.com ／ コード調査ベースの俯瞰レビュー
全体所感：作り込み（動画再生・UI・管理画面・画像/動画パイプライン）は本格的でレベルが高い。 ただしSEOの土台に致命的なミス（ドメイン不一致）があり、中古車屋の生命線である 「検索流入」が今ほぼ機能していない恐れが高い。下記を重要度順に対応してほしい。

最優先致命的・今すぐ直す（SEO土台）

1. サイト内のドメイン宣言が全部間違っている（最重要）

公開ドメインは chibagarage.com（ハイフン無し）。だがコード内の宣言が全て chiba-garage.com（ハイフン有り）＝別ドメインを指している。

client/index.html:15   canonical    = https://chiba-garage.com/   ← 別ドメイン
client/index.html:19   og:url       = https://chiba-garage.com/
client/index.html:28   twitter:url  = https://chiba-garage.com/
client/index.html:66   JSON-LD url  = https://chiba-garage.com/
client/public/robots.txt:6  Sitemap: https://chiba-garage.com/sitemap.xml

影響：canonicalが存在しない別ドメインを指すため、Googleが chibagarage.com をインデックスから外す／評価を渡さない恐れ。SNSシェアのOGPも壊れる。

対応：上記5箇所を chibagarage.com に統一（www有無もどちらかに統一してリダイレクト設定）。リスクゼロ・効果特大。

2. sitemap.xml が実在しない

robots.txt で宣言しているが、/sitemap.xml へアクセスするとXMLではなくSPAの空HTMLが返る＝ファイルが無い。各車両・各ページのURLを列挙した sitemap.xml を生成・配信する（在庫更新に追従できるよう動的生成が理想）。

3. 中身が検索エンジンに見えない（SSR/プリレンダ無し）

サーバーは全ルートに同じ空のHTMLシェルを返し、車両情報はJSで後描画（server/_core/index.ts）。クローラーにはヘッダー文言しか見えず、個々の車両（本文・写真・価格・車種名）がインデックスされない。

対応：少なくとも車両詳細ページはプリレンダリング、最低でもサーバー側で各車両の title/description/OGP/JSON-LD(Car/Vehicle schema) をHTMLに埋め込む。「車種名 中古 大崎市」で当たる個別ページを作るのが集客の鍵。

4. ページ別メタタグが無い

/buy /sell /about /consignment が全てトップと同じ title・description を使い回し（Homeのみ document.title を更新）。各ページ固有の title/description/canonical を設定する（react-helmet 等の導入）。

戦略UX設計の再考（俯瞰で一番大きい論点）

TikTok型の縦スワイプUIをメイン導線にしてよいか

動画体験の完成度は高い。だが「車を買う客」の行動とズレている：

  • 絞り込めない（価格・年式・走行距離・車種・ボディタイプでのフィルタが無い）。在庫が増えるほど目的の1台にたどり着けない。
  • 比較できない（一覧で並べて見比べる導線が無い）。
  • 検索できない。

提案：トップはグリッド一覧＋絞り込み検索を主役にし、TikTok型は「没入して見る」サブ体験に。「映える」より「探せる・比べられる」を優先するのが売上に直結する。

品質技術・コード面の指摘

パフォーマンス

  • <img> に loading="lazy"・srcset が無い → 一覧の帯域と表示速度に効くので追加。
  • AdminDashboard.tsx が約119KB/2,884行、TikTokVideoGallery.tsx が約64KB/1,721行と巨大。タブ/機能単位で分割推奨（保守性・初期ロード）。
  • recharts（重いチャート）を About 用に読み込み → 影響範囲を確認。
  • ※コード分割・画像/動画最適化・CDN preconnect・early-fetch は既に良く出来ている。

本番ビルドの作法

  • console.log が本番でも約63個発火（性能ログ・診断）→ ビルド時に除去（esbuild の drop:["console"] 等）。
  • エラーの握りつぶし：.catch(() => {}) が多数。失敗が見えず、初回再生遅延等の原因究明を妨げる。最低限ログ/トースト表示を。
  • /api/* の CORS が Access-Control-Allow-Origin: *。LAN配信都合なら可だが、公開APIなら許可オリジンを絞る。

リポジトリ衛生

  • 未使用のバックアップファイル *_3u4_baseline.tsx（Admin/Gallery）がリポジトリに残存 → 削除 or 退避。
  • .hls-cache/ .mp4-cache/ .sdr-thumb-cache/ .thumb-cache/ .upload-originals/ .db-backups/ 等のキャッシュ・DBバックアップが混入 → .gitignore で除外。

アクセシビリティ

  • 動画ギャラリーがマウス/タッチ専用。キーボード操作の代替とモーダルのフォーカストラップが無い。
  • スキップリンク（skip-to-content）無し。動画にキャプション/字幕無し。
  • ※header/main等のセマンティック構造、FABのaria-label、パンくず/ページネーションのaria対応は出来ている。

テスト

  • サーバー側ユニットテストは10ファイルあり。クライアントのテスト・E2Eが無い → 主要導線（車両閲覧・管理CRUD）に Playwright 等のE2Eを。

良い点維持すべき強み

  • JSON-LD（AutoDealer）・OGP・geoメタなどSEOの部品は揃っている（ドメイン修正で一気に活きる）。
  • 画像最適化（sharpでWebP/JPEG 3サイズ）、HLG→SDR変換、Bunny CDN、early-fetch等性能設計が本格的。
  • 特商法ページ・古物商許可番号（第221190001219号）あり＝法令面OK。
  • 管理画面（車両/メディア/ニュース/業績指標CRUD）が充実。LINE/電話/メール/Instagram の導線あり。

対応おすすめ順

  1. ドメイン5箇所を chibagarage.com に統一（数分・最重要・リスクゼロ）
  2. sitemap.xml 生成 ＋ 車両ページのメタ/プリレンダ対応
  3. ページ別メタタグの設定（/buy /sell /about /consignment）
  4. 絞り込み検索付き一覧をトップに（戦略判断）
  5. 本番ビルドのconsole除去・エラー握りつぶし解消・リポジトリ衛生
